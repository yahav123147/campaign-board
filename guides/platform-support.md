## הקבלה של Windows דרך WSL2

בוצעה ב-24.09.2026 על Ubuntu 24.04 בתוך WSL2, כמשתמש רגיל (לא root), עם סוכני Claude אמיתיים על מנוי MAX: התקנה נקייה עם `setup.sh`, `doctor` ירוק, יצירת דף מתחילתו ועד מסירה לענף הנחיתה, בנייה תחת bubblewrap ללא רשת, תצוגה מקדימה שנפתחה בדפדפן Windows, צילומי ביקורת ב-Chromium בתוך WSL2, שער QA שעבר, וסוויטת הבדיקות המלאה ירוקה בתוך WSL2, כולל בדיקות ארגז החול החיות. ריצה שנייה אימתה שביקורת עיצוב חסומה חוזרת לאדם ואינה מאושרת אוטומטית.

## דרישות התחלה

- Node.js 24 LTS ו-Python 3.12 עבור ההתקנה החדשה (מינימום: Node 20.9, Python 3.10).
- Claude Code מותקן **בתוך Ubuntu** ומחובר בחשבון עם מנוי MAX. מנוי Pro אינו מספיק לריצת הסוכנים של הבורד.
- ב-Windows: Ubuntu 24.04 ב-WSL2. WSL1, Git Bash, PowerShell ו-CMD אינם תחליף. הפרויקט חייב לשבת בתוך מערכת הקבצים של Linux (למשל `~/projects`), לא תחת `/mnt/c`.
- שכפול הריפו ב-Windows Git ולאחריו העתקה ל-WSL2 עובדים: קבצי הטקסט נשמרים עם סופי שורות של Linux.
- בלינוקס ובתוך WSL2 נדרשת חבילת `webp` (הכלי `cwebp`) להמרת תמונות ולניקוי מטא-דאטה בשלב 5.2, במקום `sips` שמגיע מובנה ב-macOS. `setup.sh` מתקין אותה יחד עם bubblewrap; אם bubblewrap כבר קיים במערכת, התקינו ידנית: `sudo apt-get install -y webp`.

## Ubuntu 24.04 רגיל

ברירת המחדל של AppArmor ב-Ubuntu 24.04 מונעת מ-bubblewrap להרים loopback בתוך user namespace, וה-doctor ידווח על כישלון בבדיקת ארגז החול. הפעילו פעם אחת:

```bash
sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0
```

ב-WSL2 אין הגבלה כזו ולא נדרש שינוי.

## יכולות אופציונליות

כיבוי יכולת אופציונלית הוא מצב תקין. הפעלתה דורשת את ההרשאות והבדיקות שלה. ה-doctor מבחין בין יכולת כבויה לבין יכולת שהופעלה אך אינה נתמכת. אין להשתמש בפרופיל או בסשן של מפתח המוצר כדי לעבור את בדיקת ההתקנה.
